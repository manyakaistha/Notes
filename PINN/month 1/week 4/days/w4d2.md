## 1. Day 2 Overview & Daily Goals

In production PINN codebases, directly calling raw `torch.autograd.grad` with manual `grad_outputs` and graph-retention flags across dozens of differential terms is error-prone. A clean architecture encapsulates differential operators into modular, reusable engine functions.

The primary goals of Day 2 are:
1. Design robust, reusable autograd wrappers for partial derivatives ($\partial_t, \partial_x, \partial_{xx}$).
2. Handle multi-variable coordinate tensors $[N, 2]$ with slice-based differentiation.
3. Manage computation graph memory and prevent graph accumulation leaks.
4. Verify operator accuracy on an analytical test field $u(t, x) = e^{-t}\sin(x)$.

## 2. Prerequisite Diagnostic Checkpoint

### Diagnostic Questions & Authoritative Solutions

#### 1. Why must `grad_outputs=torch.ones_like(y)` be supplied to `torch.autograd.grad`?
- PyTorch's autograd engine is fundamentally designed for vector-Jacobian products (VJP). For a vector-valued output $\mathbf{y} \in \mathbb{R}^N$ evaluated across $N$ batch points, PyTorch computes $\mathbf{v}^T \mathbf{J}$. Passing $\mathbf{v} = \mathbf{1}_N$ sums the derivatives across all independent batch elements, allowing PyTorch to compute the batch of point-wise derivatives $\left[ \frac{\partial y_1}{\partial x_1}, \dots, \frac{\partial y_N}{\partial x_N} \right]$ in a single efficient backward pass.

#### 2. How do we differentiate with respect to individual spatial components $x$ and $t$ when inputs are passed as a single concatenated coordinate tensor $\mathbf{X} \in \mathbb{R}^{N \times 2}$?
- Either slice the coordinates *before* passing to the network or split the concatenated gradient tensor:
  ```python
  grad_all = torch.autograd.grad(u, coords, torch.ones_like(u), create_graph=True)[0]
  u_t = grad_all[:, 0:1]
  u_x = grad_all[:, 1:2]
  ```

#### 3. What is a "computational graph memory leak" in iterative PINN training?
- If intermediate tensors computed with `create_graph=True` are stored in global lists or tracked across iterations without detaching, PyTorch keeps their entire backward history alive in GPU/RAM memory. Over thousands of epochs, this triggers Out-of-Memory (OOM) crashes.

## 4. Practical Laboratory: Building and Validating the Operator Engine

### 4.1 Concept → Code → Output → Interpretation

#### 1. Concept
We implement a modular `DifferentialEngine` class and validate its derivatives on the analytical function $u(t, x) = e^{-t} \sin(x)$ at evaluation coordinates $(t=0.5, x=\pi/3)$.

Analytical derivatives:
$$u(t, x) = e^{-t}\sin(x)$$
$$\frac{\partial u}{\partial t} = -e^{-t}\sin(x) = -u(t, x)$$
$$\frac{\partial u}{\partial x} = e^{-t}\cos(x)$$
$$\frac{\partial^2 u}{\partial x^2} = -e^{-t}\sin(x) = -u(t, x)$$

Notice that $u(t, x)$ exactly satisfies the 1D Heat Equation $\frac{\partial u}{\partial t} = \frac{\partial^2 u}{\partial x^2}$ with $\alpha = 1.0$!

#### 2. Code
```python
import torch
import numpy as np

class DifferentialEngine:
    @staticmethod
    def grad(y, x):
        """Computes dy/dx with computational graph preserved."""
        return torch.autograd.grad(
            outputs=y,
            inputs=x,
            grad_outputs=torch.ones_like(y),
            create_graph=True,
            retain_graph=True
        )[0]

    @staticmethod
    def second_grad(y, x):
        """Computes d2y/dx2 with computational graph preserved."""
        dy_dx = DifferentialEngine.grad(y, x)
        return DifferentialEngine.grad(dy_dx, x)

# Test Coordinates: (t=0.5, x=pi/3)
t = torch.tensor([[0.5]], dtype=torch.float64, requires_grad=True)
x = torch.tensor([[np.pi / 3.0]], dtype=torch.float64, requires_grad=True)

# Exact Analytical Field
u = torch.exp(-t) * torch.sin(x)

# Evaluate via Differential Engine
u_t = DifferentialEngine.grad(u, t)
u_x = DifferentialEngine.grad(u, x)
u_xx = DifferentialEngine.second_grad(u, x)

# Physics Residual: R = u_t - u_xx (Heat Equation with alpha = 1.0)
residual = u_t - u_xx

# Analytical Values
t_val, x_val = 0.5, np.pi / 3.0
exact_u = np.exp(-t_val) * np.sin(x_val)
exact_ut = -exact_u
exact_ux = np.exp(-t_val) * np.cos(x_val)
exact_uxx = -exact_u

print(f"{'Quantity':<18} | {'Engine Autodiff':<20} | {'Exact Analytical':<20} | {'Error':<12}")
print("-" * 75)
print(f"{'Field u(t, x)':<18} | {u.item():<20.12f} | {exact_u:<20.12f} | {abs(u.item() - exact_u):<12.2e}")
print(f"{'du/dt':<18} | {u_t.item():<20.12f} | {exact_ut:<20.12f} | {abs(u_t.item() - exact_ut):<12.2e}")
print(f"{'du/dx':<18} | {u_x.item():<20.12f} | {exact_ux:<20.12f} | {abs(u_x.item() - exact_ux):<12.2e}")
print(f"{'d2u/dx2':<18} | {u_xx.item():<20.12f} | {exact_uxx:<20.12f} | {abs(u_xx.item() - exact_uxx):<12.2e}")
print(f"{'Heat Residual R':<18} | {residual.item():<20.12f} | {0.0:<20.12f} | {abs(residual.item()):<12.2e}")
```

#### 4. Interpretation
The `DifferentialEngine` computes all spatial and temporal derivatives to exact double-precision machine precision ($0.00 \times 10^0$ error). Crucially, the computed heat equation residual $R = \partial_t u - \partial_{xx} u$ evaluates to identically zero, proving that our modular autodiff engine is ready to be embedded into the PINN training loop.

## 5. Daily Knowledge Mastery Checkpoint

### Problem 1: Non-linear Advection Term Implementation
**Question:** Write down the PyTorch code snippet using `DifferentialEngine` to compute the non-linear advection operator $\mathcal{A}(u) = u \frac{\partial u}{\partial x}$.  
**Authoritative Solution:**  
```python
u_x = DifferentialEngine.grad(u, x)
advection = u * u_x  # Element-wise tensor product
```

### Problem 2: Preserving Graph Continuity
**Question:** If `DifferentialEngine.grad` did not set `create_graph=True`, what would happen when calling `second_grad(y, x)`?  
**Authoritative Solution:**  
PyTorch would compute the first derivative `dy_dx` as an isolated tensor without an underlying computational history graph. Attempting to differentiate `dy_dx` with respect to `x` in `second_grad` would raise `RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn`, completely terminating the program.
